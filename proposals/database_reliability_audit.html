Executive Summary

This audit inspected 24 SQLAlchemy ORM models, 22 service files, 20 router files, 28 test files, and the complete database lifecycle (init → seed → migration → query → cache). Findings were verified through code-level analysis with adversarial challenge on every claim.

3 CRITICAL issues found — all are fixable with targeted code changes. The database itself is structurally sound (correct relationships, proper cascades, intentional nullable patterns), but the application layer has auth gaps (23+ endpoints without JWT enforcement) and one runtime crash bug (a non-existent column reference in sentiment_engine.py).

Confirmed Critical Issues

C1: 23+ Endpoints Expose User Data Without JWT Enforcement

routers/portfolio.py:508 routers/user.py routers/alerts.py:40 routers/analysis.py:467

The codebase uses a pattern where verify_access_token is called but the result is checked as if token_user is not None and token_user != user_id — meaning when no JWT is sent, token_user is None and the condition is False, so access is granted to any user_id. This affects portfolio, watchlist, alerts, trade journal, morning summary, daily action, risk analysis, macro impact, valuation history, attribution, signal warnings, and more — all via query parameter.

Agent B challenge: "Is this actually exploitable? The code comment says 'Auth optional — personal app'."
Confirmed: Yes. A curl request GET /portfolio/1 with no Authorization header returns user 1's full portfolio. The "personal app" assumption is violated as soon as the API is network-accessible (which it is).

C2: NewsArticle.related_tickers Column Does Not Exist

services/sentiment_engine.py:169,213 models/db_models.py:213-229

NewsArticle.related_tickers.like(f"%{ticker}%") is called in get_sentiment_trend() and compute_cisi(), but the NewsArticle model has no related_tickers column. The model only has ticker (singular, nullable). This will raise AttributeError at runtime whenever these functions are called.

Agent B challenge: "Are these functions actually called in production? Maybe they're dead code?"
Confirmed: get_sentiment_trend() is called from routers/market.py:/market/sentiment-trend/{ticker}. compute_cisi() is called from routers/portfolio.py:/portfolio/red-flags/{user_id}. Both are active production endpoints.

C3: P&L Reported as 0 When Current Price is Unavailable

routers/portfolio.py:558

pnl = current_value - invested if current_value > 0 else 0.0 — when current_price is None (yfinance fails, market closed, network error), current_value = shares * 0 = 0, so P&L shows ₹0 instead of -₹invested. User sees "breakeven" on a stock they may have lost everything on.

Agent B challenge: "When would current_price actually be None?"
Confirmed: yfinance returns None on weekends, market holidays, network failures, or for delisted stocks. The code has a fallback path that catches this but the current_value > 0 check runs before the fallback. A delisted stock at buy_price ₹10,000 would show P&L = ₹0 instead of -₹10,000.
